# Backend integration dependencies

All points below are **BACKEND CONTRACT REQUIRED**. David and the security, finance and compliance owners must agree the contracts before production use. This frontend does not currently connect to an admin API or database.

1. **Staff authentication/authorization:** approved staff sign-in, session, logout and server-side permission checks on every admin page and API. The middleware currently returns 503 and is a fail-closed blocker, not authentication. Preserve existing secure Starfetch session/refresh/CSRF conventions when the contract is approved; never persist tokens in localStorage.
2. **Admin reads:** authorized, paginated dashboard, users, investments, KYC, transactions, portfolios and settings data with defined search, filtering, error and empty states. Define currency precision, dates, as-of/source metadata and unknown values. Do not derive AUM, return or valuation from demo data.
3. **KYC:** approved real list/detail and authorized document access with redaction require a backend contract. Demo-only buttons simulate Verified or Rejected labels and correction sections in browser memory; they perform no real ID verification, sanctions/AML/PEP screening, compliance decision or account activation.
4. **Transaction editing:** a separate approved endpoint and field whitelist, backend authorization, validation, confirmed response and audit logging are required. Demo Add and Edit update synthetic display records in browser memory only, including mock amounts and status labels; they never access the backend or authorize real edits, payments, approvals, settlement, balances or ledger changes.
5. **User management:** real account creation, deletion, duplicate checks, identity/KYC linkage and audit logging require separately approved backend contracts and authorization. The Add/Delete dialogs mutate synthetic browser-memory rows only; verification navigation does not submit a decision.
6. **Other actions/settings:** financial processing, approvals, notifications and settings/role changes require distinct approved contracts and business/compliance/security sign-off. Preview buttons do not perform them.

The `ADMIN_DEMO_MODE=1` local-development or Vercel Preview demo is intentionally unauthenticated and serves synthetic fixtures, never customer data. Vercel Deployment Protection is mandatory for online previews; the application cannot verify that protection is enabled. Do not expose it publicly, connect real APIs to it or enter real credentials. Production fails closed until real backend authorization is implemented. See README.md for setup and build/runtime restrictions.
